# Emart KB

이 디렉토리는 이마트 영수증 파싱을 위한 규칙 기반 Knowledge Base를 정의한다.

이마트는 전체 구조는 단순하지만, 상품/할인 표현 방식이 다양하고 변형이 많은 것이 특징이다.

---

# 기본 구조

이마트 영수증은 다음과 같은 흐름을 가진다:

상품명
→ 상품 상세 (code + unit_price + qty + total_price)
→ (선택) 할인 라인
→ 다음 상품

---

# 상품 구조

## item_name

상품명 라인

예:
01 떡붕어싸만코  
02 오뚜기 컵밥 옛날 잡  
(J)무항생제볶음탕용  
(JN)친환경참타리버섯  

---

## item_detail

상품 상세 라인

기본 구조:

code + unit_price + qty + total_price

예:

8801121027097 1,450 1 1,450  
8801013770025 280 4 1,120  

---

## 통합형 (중요)

상품명 + 상세가 한 줄에 결합된 경우 존재

예:

퍼실 딥클린 파워젤 26,980 3 80,940  
* 01 (Ph)돌바나나(송이) 2,280 1 2,280  

---

# 수량 규칙

- 기본: 별도 필드로 존재
- 예외: 누락 가능

예:
1500000018153 5,480 5,480  
→ qty = 1로 보정

---

# 코드 규칙

- 일반적으로 13자리 바코드
- 일부 * prefix 존재

예:
*8801013770025 → 8801013770025

---

# 할인 구조 (중요)

이마트는 "키워드 기반"이 아니라  
**위치 기반 할인 구조**를 가진다.

---

## 할인 라인 형태

프로모션명 + 할인금액

예:

컵밥류 2+1 -1,660  
샌드류5개5천 -5,000  
[앱]고소미50% -1,400  

---

## 특징

- 마지막 음수 금액이 핵심
- 프로모션명은 보조 정보
- 할인은 대부분 직전 상품에 적용

---

## 해석 규칙

discount_detail은:

- 항상 직전 item에 귀속
- 금액만 추출하여 사용

---

# 전역 할인 (Receipt Discount)

영수증 하단에 존재하는 할인

예:

결제할인 : 2201606006 -4,410  
삼성카드할인 : 2211101938 -5,000  
[앱]룰렛3천원 : 2201606243 -3,000  

---

## 특징

- 특정 상품이 아닌 전체 할인
- item에 귀속하지 않음

---

# 특이 항목

## fee (공병)

예:

공 병 600  

→ 상품이 아닌 별도 금액 항목

---

# 정규화 포인트

## 괄호 제거

- (J), (JN), (Ph) 제거

예:
(J)무항생제볶음탕용 → 무항생제볶음탕용  

---

## 대괄호 태그

- [앱] 등은 유지 (분류용)

---

## 숫자 보정

- qty 누락 → 1
- 3-token 구조 → qty=1

---

## OCR 보정

- 제대상금액 → 결제대상금액
- 부 가 세 → 부가세

---

# 노이즈 라인

다음 라인은 제거 대상:

- 상품명 단 가 수량 금 액
- 상품코드 단 가 수량 금 액
- 사업자번호 포함 판매자 정보

---

# 합계 / 종료 라인

다음 라인은 item 파싱 종료 기준:

- 결제대상금액
- 합 계
- 부 가 세
- 면세 물품
- 과세 물품

---

# 파서 출력 예시

입력:

8801121027097 1,450 1 1,450  

출력:

{
  "line_type": "item_detail",
  "code": "8801121027097",
  "qty": 1,
  "unit_price_raw": 1450,
  "price_raw": 1450
}

---

# 핵심 요약

- 구조는 단순하지만 표현 방식이 다양하다
- 할인은 키워드가 아니라 위치 기반으로 해석한다
- 상품 + 상세가 한 줄에 결합된 경우 존재
- qty 누락 케이스 존재
- Parser는 구조만 추출하고 의미 해석은 하지 않는다

---

# 한 줄 정의

Emart는 위치 기반 할인 구조를 가지는 유연한 포맷의 영수증이다.
